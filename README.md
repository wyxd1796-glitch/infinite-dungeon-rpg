# INFINITE — 무한 던전 RPG

Python / PySide6 데스크톱 게임입니다. **1.1.0: 콘텐츠 확장 1차(전투·파밍)** 를 적용했습니다.

몬스터 40종, 보스 10종, 접두어 20종, 장비 90종, 옵션 30종, 소비품 20종, 재료 20종, 환경 10종, 층 유형 5종, 공통 효과 15종을 실제 전투·상점·드롭에 연결했습니다. 스킬 5종·이벤트 10종·업적 7종과 8개 메인/22개 하위 화면은 유지합니다. 상세 규칙과 원문 보완표는 [1차 구현 문서](docs/PHASE1.md)를 참고하세요.

## 실행

Windows에서 `start.bat`을 더블클릭하거나 이 폴더에서 `python main.py`를 실행합니다.

처음 설치하는 PC에서는 먼저 `python -m pip install -r requirements.txt`를 실행하세요. Python 3.11 이상을 권장합니다. 이 작업 환경에서는 Python 3.14 / PySide6 6.11.2로 실행 및 테스트했습니다.

## 첫 플레이

1. 상단 메인 선택기에서 **거점 → 휴식**을 선택합니다.
2. **던전 입장 → 입장하기**를 클릭합니다.
3. **던전 → 탐험 → 탐험 진행**을 클릭합니다.
4. 적을 만나면 오른쪽 **공격 / 사용 / 방어** 값을 클릭합니다. 현재 전투 자동은 그 전투만 계산하고 위험 HP에서 멈춥니다.
5. 탐험 3회 완료 후 다음 층으로 이동합니다. 10층마다 탐험 2회 후 보스를 이겨야 합니다.
6. 전투 밖에서 귀환해 회복·구매·강화·보관을 이용합니다. 초기 장비는 없으며 상점에서 무기를 구매해 장착할 수 있습니다.
7. 상점/가방의 슬롯·종류 필터와 이름 검색(입력 후 Enter)으로 아이템을 찾습니다. 가방 초과 보상은 **가방 → 획득 대기**에서 받기·버리기로 처리합니다.

이름 열은 설명, 오른쪽 값 열은 조회·선택·실행을 담당합니다. 선택기 변경만으로 행동이 실행되지 않습니다. 긴 문구는 마우스를 올리거나 행을 오른쪽 클릭하면 전체 내용을 확인할 수 있습니다.

이벤트의 상황 설명과 상점의 상품 설명은 제목 행 바로 아래의 두 열 병합 셀에 줄바꿈하여 전문을 표시합니다. 이 설명 셀만 내용과 창 너비에 따라 높이가 바뀌며 일반 속성 행은 25px을 유지합니다. 상점의 무작위 장비는 구매 전 기본 능력치 범위를 표시하고, 실제 레벨·등급·옵션은 구매 시 결정됩니다.

첫 번째 선택기 오른쪽의 작은 아이콘은 순서대로 **기록 / 설정 / 거점** 바로가기입니다. 거점 아이콘은 휴식 화면을 열며 던전에서 실제 귀환을 실행하지 않습니다. 상단 **핀 버튼**을 켜면 파란 배경과 노란 핀으로 표시됩니다.

## 창과 저장

- 기본 창 268×861, 최소 250×400. 제목 영역 드래그로 이동하고 가장자리 드래그로 크기를 변경합니다.
- 제목 오른쪽: 최소화, 항상 위, 닫기. 카테고리 제목 클릭으로 접기/펼치기.
- 두 열의 경계를 드래그하면 비율이 바뀝니다. 행 높이는 계속 25px입니다.
- `saves/slot_1.json` ~ `slot_3.json`: 게임 저장. `saves/ui.ini`: 창 위치, 크기, 화면, 접힘, 스크롤, 열 비율.
- 자동 저장 및 종료 저장, 수동 저장/불러오기, 이전 정상 저장 `.bak` 복구를 지원합니다. 손상 원본은 `.corrupt`로 보존합니다.
- 삭제한 슬롯은 `.deleted`로 보존하며, 현재 슬롯을 삭제하면 수동 저장 또는 새 게임 전까지 자동 저장을 차단합니다.
- 스키마 1 저장은 원본 `.pre-v2.bak`을 만든 뒤 스키마 2로 이전합니다. 기존 장비와 진행 중 전투/이벤트를 보존합니다.
- 저장 읽기에 실패하면 안내를 표시하며 기존 슬롯을 새 게임으로 자동 덮어쓰지 않습니다.

## 구성

- `core/game_engine.py`: 공개 엔진 진입점
- `core/expansion_engine.py`, `combat.py`, `loot.py`: 탐험·효과·전투·전리품·상점
- `core/catalogue.py`: 원본 보존 어댑터와 활성 260개 정의 검증
- `core/legacy_engine.py`, `migrations.py`: 공통 명령과 구버전 진행 호환
- `core/content.py`: JSON 콘텐츠 검증, 조건 및 콘텐츠 팩 로딩
- `core/save_manager.py`: 3슬롯, 원자적 교체, 백업 복구
- `ui/property_window.py`: 8개 메인 / 22개 하위 속성 화면
- `content/base/`: 기존 호환 정의, 유지하는 스킬·이벤트·업적
- `content/source/catalogue_v4.json`: 변경하지 않은 전체 원본
- `content/catalogue/selection.json`: 첫 확장 선택 범위와 실행 보완값
- `docs/IMPLEMENTATION.md`: 기획 대응, 미확정 수치의 적용 가정, 후속 검증 범위
- `artifacts/`: UI 캡처 및 검증 결과

## 검증

```powershell
python -m unittest discover -s tests -v
python -m tests.simulate_expansion
```

테스트는 실사용 저장 대신 `artifacts/tests/`를 사용합니다. `tests.simulate_expansion`은 고정 난수 시드로 장비 100,000개·몬스터 100,000회 추첨, 층별 전투 표본 및 3,000회 진행 결정을 검증합니다. 이 시뮬레이션은 기능과 수치 불변식 검사이며 게임 난이도의 최종 승인을 뜻하지 않습니다.

## 콘텐츠 추가

`content/packs/<pack_id>/manifest.json`과 기본 팩과 같은 종류의 JSON 파일을 추가합니다. manifest에는 `pack_id`, `version`, `schema_version: 1`, `dependencies`, `enabled`, `content_files`를 지정합니다. ID는 `pack.type.name` 형태로 기존 ID와 겹치지 않아야 합니다.

기존 팩 로더는 저장 호환 정의와 기존 이벤트·스킬 확장에 사용합니다. 첫 확장의 몬스터·장비·접두어·보스·옵션 출현 풀은 선택 카탈로그로 통일되므로 그 종류의 새 팩을 넣는 것만으로 출현하지 않습니다. 활성 범위 변경은 어댑터·효과 처리·검증을 함께 확장해야 합니다. 없는 의존성, 중복 ID, 없는 참조, 알 수 없는 효과/조건, 잘못된 필수 필드가 있는 추가 팩은 전체를 비활성화하고 안내합니다. 새 전투 규칙과 새 효과 유형은 엔진 확장이 필요합니다. 팩 삭제 시 이미 얻은 장비는 보존되며 원형이 없으면 장착/강화가 제한됩니다.

`tools_build_content.py`는 기본 JSON을 재생성하는 개발 도구입니다. 직접 편집한 콘텐츠를 보존하려면 다시 실행하지 마세요.
