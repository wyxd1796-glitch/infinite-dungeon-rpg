# INFINITE — 1.2.0 이후 전체 개발 상세 기획서

작성일: 2026-10-17 · 문서 버전: 1.0 · 대상: 현재 Windows/Python/PySide6 데스크톱 게임

## 문서 사용법과 현재 상태

이 문서는 다음 10단계를 모두 마친 정식 배포판까지의 개발 기획이다. **문서를 저장한 것이 아래 기능을 구현하거나 밸런스를 승인했다는 뜻은 아니다.** ‘현재’는 저장소에서 확인한 사실, ‘원본 기준’은 원본 JSON의 설계값, ‘제안’은 앞으로 적용·검증할 실행 기준이다. 수치 제안은 먼저 테스트용 설정에 넣고 검증한 뒤 릴리스 설정으로 승격한다. 근거 없이 원본이나 실사용 저장을 덮어쓰지 않는다.

- 현재 구현: 1.2.0, 저장 스키마 3, 스킬 13개, 이벤트 30개, 기존 카탈로그 활성 정의 260개, 업적 7개.
- 현재 화면: 8개 메인/22개 하위 화면, 기본 268×861, 최소 250×400, 설명 줄바꿈과 세로 스크롤 지원.
- 현재 검증 기록: 회귀 테스트 100개 통과. 단계별 수치는 [PHASE2.md](PHASE2.md) 참조. 본 문서 작성 과정에서는 이 테스트를 재실행하지 않았다.
- 사용자 확인: 실행 정상. 실행 관련 수정은 보존한다.
- 남은 문제: 100→101층 난이도 급락, 고층 보스 난이도, 방어구·물약 성장 정체, 회복 스킬의 낮은 자동 사용 빈도.
- Git 상태: 1.2.0 변경과 실행 수정이 아직 작업 폴더에 있다. 원격 업로드는 별도 요청 범위다.
- 전체 콘텐츠 대장: [CONTENT_INVENTORY.md](CONTENT_INVENTORY.md). 원본 1,305개 정의를 빠짐없이 열거하며 현재 연결 상태와 예정 단계를 표시한다.
- 실행 체크리스트: [ROADMAP_TASKS.md](ROADMAP_TASKS.md). 각 작업의 산출물과 완료 상태를 기록한다.

### 전체 완료의 정의

새 PC에서 실행할 수 있고, 기존 저장을 이전할 수 있으며, 새 게임 → 일반 등반 → 직업·전직 → 제작·수집 → 특수 콘텐츠 → 환생 → 다음 회차가 끊김 없이 연결되어야 한다. 1,305개 원본 항목은 각각 ‘실행 연결’, ‘동일 기능으로 통합’, ‘근거 있는 제외’ 중 하나로 판정되어야 한다. 최종판에서 단순 ‘미검토’·‘추후 구현’ 상태는 허용하지 않는다. 통합·제외는 원본 ID를 삭제하는 것이 아니라 대응 ID와 사유를 대장에 남기는 일이다.

## 공통 설계 원칙

### 데이터와 규칙의 우선순위

1. 실제로 승인된 현재 규칙을 기존 저장에 적용한다.
2. 신규 기능은 원본의 구조화된 수치·연산자·운영 규칙을 출발점으로 삼는다.
3. 이 기획의 제안값은 별도 버전의 실행 정의에 둔다. 변경 사유와 비교 결과를 기록한다.
4. `base_catalogue_v3.event_runtime_overrides`도 원본 대조 대상에 포함한다. 빈 결과 필드나 문자열 식은 자동 실행하지 않는다.
5. 이미 차별화한 2차 스킬·이벤트를 이후 전체 카탈로그 활성화 때 원본 초안으로 되돌리지 않는다.
6. ID는 영구 식별자로 유지한다. 이름 변경과 밸런스 변경을 이유로 기존 인스턴스를 다른 물건으로 바꾸지 않는다.

### 공통 구현 계약

- 모든 변경 명령은 `execute()`의 검증 → 비용 차감 → 효과 적용 → 결과 확정 → 저장 경로를 통과한다. 실패하면 자원·턴·난수 모두 원상복구한다.
- 조회, 검색, 정렬, 장비 비교, 화면 이동은 게임 난수·턴·자원·보상을 변경하지 않는다.
- 스킬·효과·아이템·지역·해금 조건을 선언형 데이터로 정의한다. `eval`이나 원본 문자열 실행은 사용하지 않는다.
- 피해·회복·드롭·경제 보정은 공유 계산기로 집약한다. UI는 같은 계산기의 읽기 전용 결과를 표시한다.
- 확률은 내부 비율과 표시 %/%p를 구분한다. 정수화 시점과 상한을 규칙별로 명시한다.
- 명령 종류, 콘텐츠 버전, 저장 스키마 버전, 밸런스 버전을 분리한다. 새 저장 필드가 생길 때만 스키마를 올린다.
- 이미 저장된 전투·이벤트·제작 결과는 재추첨하지 않는다. 새 규칙은 새 조우부터 적용한다.
- 공간 부족 보상은 획득 대기로 보존한다. 사용자 동의 없이 자동 판매·삭제하지 않는다.
- 반복 보상은 `run_id`·대상 ID·보상 종류로 지급 이력을 구분한다. ‘누적 1회’와 ‘회차별 1회’를 혼용하지 않는다.
- 잠긴 기능은 요구 조건과 달성 현황을 표시한다. 효과가 없는 장식 버튼을 노출하지 않는다.

### 저장과 검증의 공통 계약

- 저장 파일을 읽은 뒤 검증하고, 이전 전 백업을 만든다. 이전 중 실패하면 원본을 유지한다.
- 3슬롯, 자동 저장, 수동 저장, `.bak` 복구, `.corrupt` 보존을 모든 단계에서 유지한다.
- 개발 테스트는 `artifacts/`의 임시 저장만 사용한다. 실사용 `saves/`를 테스트 입력으로 자동 사용하지 않는다.
- 회귀 검사 외에 신규 규칙의 성공·실패·경계값·재접속·공간 부족·중복 클릭을 검사한다.
- 시뮬레이션 결과는 기능 검증과 난이도 평가를 구분한다. 평균만 보고 희귀 실패를 숨기지 않는다.
- 적용 전후 동일 시드, 장비 조건, 스킬 포인트 예산, 자동 정책을 기록한다.
- 개발용 진단은 로컬에만 남긴다. 원격 통계 전송이나 계정 시스템은 이번 범위에 없다.

## 2단계 — 밸런스 기준과 자동 전투 정책 확정

### 평가 기준 제안

‘적정 준비’는 해당 구간에서 해금된 장비, 실제 획득한 능력치·스킬 포인트, 과도하지 않은 강화, 구매 가능한 물약으로 정의한다. 테스트용 무한 골드·최대 강화는 별도 상한 표본으로만 사용한다.

| 항목 | 초기 목표 제안 | 측정 방법 |
|---|---|---|
| 일반전 | 중앙값 2~5행동 | 동일 구간 200회 이상 |
| 정예전 | 중앙값 4~9행동 | 일반전과 동일 장비 |
| 보스전 | 중앙값 8~18행동 | 같은 구간의 보스 표본 |
| 준비된 보스 승률 | 60~85% | 20시드 이상, 표본 수와 오차 함께 기록 |
| 주요 빌드 간 승률 차이 | 15%p 이내를 지향 | 같은 포인트·장비 예산 |
| 일반층 경계 난이도 변화 | 20% 이내를 지향 | 인접 일반층끼리 비교; 보스→일반 직접 비교 금지 |
| 회복·보급 순환 | 통상 3~8개 층 진행 후 거점 재정비 | 중간·하위 성능 빌드도 별도 측정 |
| 장비 갱신 | 10층 구간 안에 유의미한 선택 1회 이상 지향 | 단순 드롭 개수가 아닌 실제 교체·제작 후보 |

목표 미달이면 수치·정책·테스트 전제 중 원인을 먼저 분류한다. 특정 빌드에 맞추기 위해 전체 적 수치를 일괄 하향하지 않는다.

### 구현할 정책

1. 밸런스 설정을 전투, 성장, 경제, 드롭, 자동 사용으로 나누고 버전과 변경 이유를 기록한다.
2. 자동 전투의 공통 순서를 ‘위험 HP 중단 → 사용 가능한 회복 수단 결정 → 일반 스킬 우선순위 → 공격’으로 명시한다.
3. 회복 수단 설정을 `물약 우선`, `회복 스킬 우선`, `효율 우선` 세 가지로 제공한다. 기존 저장은 물약 우선으로 유지한다.
4. 효율 우선은 실제 부족 HP에 대한 유효 회복량을 먼저 비교하고, 동률이면 MP를 쓰는 스킬을 우선한다. 상태 제거 필요 시 사용 가능한 정화 스킬을 먼저 고려한다. 위험 중단 설정을 우회하지 않는다.
5. 일반 공격 스킬에 MP 예약량 설정을 추가한다. 기본 0이며 사용자가 응급 치료 1회분 등을 남길 수 있게 한다. 회복 스킬에는 예약 제한을 적용하지 않는다.
6. 자동 정책 미리보기는 ‘다음 행동과 이유’를 보여 주되 난수를 소비하지 않는다.
7. 기존 상태이상·피해 상한과 직업 이후 적용할 능력치 합성 순서를 명세한다. 치명 75%, 회피 45%, 반격 40%, 일반 피해 감소 70%, 흡혈 25%, 상태 저항 75%, 추가 보상 200%를 기준으로 유지한다.
8. 2차 철벽 방어의 별도 피해 배율은 현재 규칙으로 보존한다. 상한을 바꿀 경우 영향받는 저장 버전을 별도 구분한다.

### 저장·UI·검증

- 자동 정책과 MP 예약량만 추가 저장한다. 기존 저장 기본값은 현재 행동과 같아야 한다.
- 전투 설정 화면에 회복 정책·예약 MP·다음 자동 행동 이유를 표시한다.
- 조합별 승률, 전투 턴 P50/P90, 물약·MP 소비, 귀환 빈도, 골드 순수익, 드롭, 사망층, 스킬 사용률을 수집한다.
- 물약 없음, MP 부족, 침묵, 전부 대기 중, 회복 낭비, 상태이상만 존재, 위험 중단 경계값을 검사한다.
- 산출물: `docs/BALANCE_SPEC.md`, 버전별 설정, 다중 시드 보고서. 목표와 실제 결과가 함께 제시되면 완료한다.

## 3단계 — 고층·몬스터·장비·효과·이벤트 확장

### 콘텐츠 범위

원본 전체 범위는 몬스터 150, 보스 40, 접두어 50, 장비 330, 옵션 100, 소비품 50, 재료 60, 환경 30, 층 유형 5, 공통 효과 40이다. 현재 활성 수량과 차이는 콘텐츠 대장으로 관리한다. 단순 개수 증가가 아니라 출현→전투→보상→성장 사용처까지 연결한다.

### 구현 순서

1. 효과 EF016~040의 연산자부터 지원한다. 지속 피해, 명중 감소, 일반/스킬 피해 감소, 혼란, 회피 감소, 취약, MP 비용 증가, 최대 MP 감소, 치명 강화, 보호막, MP 흡수, 치명 피해, 반격, 1회 생존, 보상 강화의 시점·대상·중첩·면역을 각각 정의한다.
2. `actor`, 행동 전후, 명중 후, 피해 후, 치명 후, 치명 피해 직전, 처치 보상 시점을 공유 처리기로 정리한다. 효과 문자열에 의존하는 분기를 없앤다.
3. 101~200층을 먼저 열고 1~100층 회귀 검사 후 201~300, 301~400 순으로 활성화한다. 각 구간은 몬스터·보스·장비·환경·소비품을 함께 출시한다.
4. 몬스터는 종족, 역할, 공격 패턴, 상태효과, 드롭, 최소/최대 출현층, 가중치를 모두 채운다. 접두어의 범주 중복 제한도 유지한다.
5. 보스 40종은 10층마다 배치한다. 보스마다 기본 원형, 단계 전환, 행동 순서, 특수 효과, 대응 방법, 최초 보상을 정의한다. 순수 수치 상승만 있는 보스는 패턴이나 보상에서 구분한다.
6. 환경 30종은 원본 지역 반복 범위와 대응한다. 환경 순환과 보스 400층 순환을 별도 계산해 서로 다른 주기를 하나의 `%100`으로 처리하지 않는다.
7. 401층 이후는 보스 카탈로그 순환과 절대층 성장 배율을 분리한다. 새 순환의 처음 원형이 약하더라도 실제 적 능력치·보상은 이전 순환보다 하락하지 않도록 구간 정규화 계수를 둔다.
8. 몬스터 원형의 역할 차이는 유지하고, 인접 일반층 HP·공격력·방어력·보상의 평균과 P90을 비교하여 정규화한다. 보스 직후 일반층이 보스보다 약한 것은 정상이며, 이전 일반층보다 급락하는 현상을 문제로 본다.
9. 기존 장비의 굴림값·옵션·강화는 보존한다. 새 드롭부터 장비 생성 규칙 버전을 기록한다. 재계산으로 기존 장비를 몰래 약화하지 않는다.
10. 방어구의 DEF/HP와 마력 장비의 MP 성장곡선을 무기 성장과 함께 설계한다. 기본안은 `원형 기본값 + 슬롯별 계수×장비 레벨`이며 계수는 2단계 목표로 보정한다. % 옵션은 동일한 선형 가산을 적용하지 않고 별도 상한을 둔다.
11. 새 물약은 고층에서 필요한 회복 비율을 유지하도록 해금층·회복량·가격을 함께 조정한다. 기존 물약을 삭제하거나 이름만 바꾸지 않는다.
12. 옵션 100종은 슬롯 제한, 발동 조건, 중복 그룹, 값 범위, 강화 적용 여부를 명시한다. 옵션이 붙을 수 있으나 효과가 구현되지 않은 조합을 금지한다.
13. 이벤트는 원본 EVT001~100 범위를 먼저 검토한다. 현재 20개 실행 정의를 보존하고 나머지는 서술·조건·비용·결과·실패·지나가기를 작성한다. 직업·유물 등 미구현 기능에 의존하면 후속 단계로 명시 이동한다.

### 데이터와 UI

- 실행 선택 목록을 ‘각 종류 앞에서 N개’ 방식에서 명시적 ID/지역 목록으로 전환한다. 미지원 항목이 끼어 있어도 안전하게 선별할 수 있어야 한다.
- 지역은 ID, 표시명, 최소/최대층, 반복 정책, 출현풀, 환경 보정, 보스 연결, 드롭 연결을 가진다.
- 효과 정의는 대상, 시점, 수치 단위, 지속기간, 중첩 방식, 최대 중첩, 면역, 관련 태그를 가진다.
- 장비 인스턴스에 생성 규칙 버전을 추가한다. 진행 중 전투에는 사용한 규칙 버전/적 스냅샷을 보존한다.
- 탐험에 지역·위험 요인·다음 보스, 전투에 다음 행동·상태 설명, 장비에 현재 대비 차이·수치 범위를 표시한다.
- 패턴이 달라졌어도 이미 진행 중인 보스를 재생성하지 않는다. 다음 전투부터 새 규칙을 적용한다.

### 검증과 완료 조건

- 1~400층 모든 층에서 비어 있지 않은 조우·장비·옵션 풀이 존재해야 한다.
- 99/100/101, 199/200/201, 299/300/301, 399/400/401과 800, 1,000, 10,000층을 점검한다.
- 25개 추가 효과 각각 발동·비발동·중첩·만료·저장 복원·동시 사망을 검사한다. 생존 효과는 정확히 1회만 작동해야 한다.
- 장비/몬스터 각각 100,000회 이상 추첨, 조합별 고층 전투, 동일 시드 진행을 수행한다.
- 새 장비를 얻어야 다음 구간으로 갈 수 있는 성장 경로를 확인하고, 보스 때문에 모든 조합이 영구적으로 막히는 구간을 해소한다.
- 산출물: 지역·보스·효과 명세, 활성 목록, 밸런스 설정, 테스트, 전후 비교표. 고층 진행과 기존 저장 호환이 모두 충족되어야 완료한다.

## 4단계 — 제작·분해·정제와 경제 순환

### 기능 설계

1. 거점에 제작 기능을 추가한다. 기존 메인/하위 화면 구조를 유지하고 거점 화면 내부에서 제작·분해·정제 탭 또는 선택기를 제공한다.
2. 제작은 슬롯과 원형을 선택해 장비 1개를 생성한다. 최초 도입은 해금된 일반~희귀 원형으로 제한하고 상위 등급 확정 제작은 도전 보상과 연계할 후속 조리법으로 분리한다.
3. 제작 조리법은 ID, 결과 원형/등급 정책, 재료 ID·수량, 골드, 해금층, 해금 조건, 결과 개수, 버전을 가진다. 조리법 자체가 무작위로 바뀌지 않는다.
4. 결과 장비의 옵션을 무작위로 정할 경우 미리보기는 가능한 범위만 보여 준다. 제작 실행 시 비용과 난수를 한 번 소비하고 결과 스냅샷을 저장한다.
5. 분해는 선택 장비의 등급·레벨·강화에 따른 재료를 준다. 장착·잠금·즐겨찾기 장비는 대상에서 제외한다. 묶음 분해 전 대상과 총 보상을 보여 준다.
6. 정제는 같은 계열 하위 재료를 상위 재료로 바꾼다. 초기 제안은 5:1과 골드 비용이며 역정제는 제공하지 않는다.
7. 강화 재료 MAT016~018의 기존 환산 단위는 별도 규칙으로 유지한다. 정제 수량과 강화 환산 단위를 혼동하지 않는다.
8. 제작 실패 확률은 초기 버전에서 두지 않는다. 강화 확률은 기존 규칙을 유지하고 제작의 불확실성은 허용된 옵션 굴림에만 둔다.
9. 창고 이동·판매·분해에 장비 잠금 속성을 추가한다. 잠금은 전투 능력치에 영향을 주지 않는다.
10. 신규 재료 60종 모두에 최소 하나의 획득처와 사용처를 지정한다. 아직 소비처가 없는 재료는 보상 풀에 넣지 않는다.

### 경제 수치 제안

- 제작 재료 수량: 등급별 4/8/16개에서 시작하고 구간별 기대 획득량으로 보정한다.
- 분해 환급은 해당 장비의 동일 조리법 제작 재료보다 적어야 한다. 상점 구매→분해→제작→판매 순환의 기대 골드 수익을 양수로 만들지 않는다.
- 강화 실패 시 아이템 소멸 없음, 이미 쓰인 비용 환급 없음이라는 기존 규칙을 유지한다.
- 업그레이드 1회 비용은 해당 구간 일반전 골드 수입 기준으로 설명할 수 있게 정한다. 비용이 증가할 때 재료와 골드 양쪽이 동시에 과도한 병목이 되지 않게 한다.
- 거래 가격·제작 비용·분해 보상을 한 보고서에서 비교한다. 기본안은 판매와 분해가 상황에 따라 선택될 수 있게 하는 것이다.

### 저장·실패·UI

- 장비 잠금, 해금 조리법, 제작 기록, 경제 규칙 버전을 저장한다. 기존 장비의 잠금 기본값은 꺼짐이다.
- 재료/골드 부족, 해금되지 않은 조리법, 장착물 분해, 결과 공간 부족은 비용 소비 전에 판정한다.
- 결과 공간 부족은 제작 자체를 거절하는 정책으로 시작한다. 도전·드롭 보상에 사용하는 획득 대기와 유료 제작의 행동을 구분한다.
- 미리보기에는 소비 합계, 보유 수량, 결과 범위, 성공 확률 100%, 공간 요구를 표시한다.
- 산출물: 조리법 JSON, 경제 표, 제작/분해/정제 명령, 잠금 UI, 저장 이전 코드.

### 완료 조건

단일·묶음 처리, 재접속, 중복 클릭, 정수 경계, 가방 최대치, 잠금 보존을 검사한다. 자동 제작/분해 순환으로 자원을 복제할 수 없어야 한다. 실제 진행에서 판매·강화·제작 중 선택할 이유가 있어야 하고 모든 활성 재료에 사용처가 있어야 한다.

## 5단계 — 직업·전직·스킬 트리·전체 스킬 확장

### 직업과 전직

| 기본 직업 | 누적 최고층 해금(원본) | 전직 후보 | 핵심 역할 |
|---|---:|---|---|
| 전사 | 0 | 기사 / 광전사 | 방어·반격 / 위험을 감수한 공격 |
| 도적 | 30 | 암살자 / 그림자 | 치명·처형 / 회피·상태이상 |
| 마법사 | 50 | 화염술사 / 현자 | 지속 피해·마력 / MP 운용·스킬 |
| 궁수 | 70 | 저격수 / 사냥꾼 | 관통·단일 공격 / 정예·파밍 |
| 성직자 | 100 | 성기사 / 정화사 | 생존·보호막 / 회복·상태 제거 |

1. 직업 5개와 전직 10개는 원본 ID와 보너스 데이터를 명시적 실행 연산자에 연결한다. 설명에만 있는 직업 효과를 허용하지 않는다.
2. 전직 조건은 캐릭터 15레벨과 현재 회차 50층 보스 처치다. 전직 비용 0, 회차당 1회, 환생 전 재선택 불가를 원본 기준으로 적용한다.
3. 신규 캐릭터는 전사로 시작한다. 기존 캐릭터 이전 시 기본 전사를 부여하고, 이미 해금된 직업을 1회 고를 수 있는 전환권을 제안한다. 이는 원본의 ‘환생 직후 선택’에 대한 이전 전용 보완이며 사용 여부를 저장한다.
4. 일반 직업 변경은 8단계 환생 후 선택으로 연결한다. 그 전에는 다른 직업의 전투 검증을 테스트 캐릭터로 수행한다. 개발 중이라는 이유로 무제한 직업 변경을 실사용에 노출하지 않는다.
5. 직업별 무기 제한은 원본처럼 기본적으로 두지 않는다. 제한이 필요해질 경우 기존 장비 사용 불가 문제를 별도 기획한다.

### 트리와 스킬

- 트리는 직업별 3개 가지×3개 노드, 총 45개다. 각 노드의 원본 연산자, 선행 노드, 티어, 비용, 효과를 목록화한다.
- 트리 포인트는 10레벨마다 1 P, 티어별 비용 1/2/3, 요구 레벨 10/25/50을 원본 기준으로 한다. 기본 스킬 포인트와 별개 자원이다.
- 트리 재분배는 거점에서 `레벨×200 G`, 확인 후 수행한다. 기존 기본 스킬 무료 재분배와 명확히 구분한다.
- 저장 이전 시 지급돼야 할 트리 포인트는 `floor(현재 레벨/10)`과 지급 이력을 비교해 한 번만 지급한다.
- 원본 스킬 70개 전체를 검토한다. 기존 강타·연속 베기·회복·무기 숙련·철벽과 원본 대응 항목은 중복 학습시키지 않고 별칭 매핑으로 통합한다. 기존 투자·효과는 별도 규칙 버전으로 보존한다.
- 이미 구현한 신규 8개는 현재 실행 정의를 유지한다. 나머지는 공격, 방어, 회복, MP, 상태 제어, 파밍 역할로 분류하고 같은 역할 안에서도 비용·대기·조건이 달라야 한다.
- 다단 공격, 정화, MP 회복, 생존 효과, 보스/정예 특화, 강화 할인 등 모든 스킬의 의존 기능을 확인한다. 효과 엔진이 없으면 먼저 구현한다.
- 직업이 바뀌어도 공통 스킬을 삭제하지 않는다. 직업 전용 트리 효과만 해당 직업에서 활성화한다.
- EVT101~150은 직업별 선택·능력치 조건·분기형 탐험에 활용하되, 특정 직업이 아니어도 무료로 나갈 수 있어야 한다.

### 데이터·UI·검증

- 저장: `class_id`, `specialization_id`, 해금 직업 목록, 트리 학습 목록·잔여 포인트·지급 기록, 이전 전환권.

## 6단계 — 유물·도감·수집 보상

5. 중복은 기본 가루 3개로 전환한다. 시설·환생 효과가 추가돼도 원본 최대 7개 상한을 적용한다.
6. 최대 5레벨. 레벨 2/3/4/5의 가루 비용은 2/4/8/16, 골드는 500/1,500/4,500/13,500을 기본으로 하되 개별 원본 정의가 다르면 그 값을 기록한다.

## 8단계 — 환생·회차·영구 성장

2. 새 직업을 먼저 선택하고 결과 요약을 확인한다. 조건을 충족하지 못한 직업은 선택 불가다.
3. 환생 직전 전용 백업을 만든 뒤 새 상태를 메모리에서 완성한다.
4. 장비 해제, 공간 배치, 영구 상태 복사, 새 회차 생성, 포인트 지급을 하나의 원자적 저장으로 확정한다.
5. 저장 실패 시 현재 회차를 그대로 유지하고 재시도한다. 포인트를 먼저 지급하고 나중에 초기화하지 않는다.
6. 완료 화면에서 새 직업·계승 포인트·유지 장비 위치를 안내한다.

### 검증과 완료

- 동일 상태에서 환생 버튼 중복 실행, 저장 도중 실패, 환생 전후 강제 종료, 과거 백업 복구를 검사한다.
- 슬롯별 회차·누적 최고층·누적 보상 기록이 섞이지 않아야 한다.
- 1→2→3회차 실제 진행, 100회 환생 상태 전이, 모든 계승 최대치에서 상한·정수 계산을 검증한다.
- 환생으로 기본 스킬 포인트·무료 보급·도전 최초 보상·현상금 보고를 복제할 수 없어야 한다.
- 산출물: 환생 상태 변환 명세, 유지/초기화 표, 전용 백업·저장 코드, 계승 UI, 연속 회차 보고서. 새 회차를 정상 진행하고 다시 환생할 수 있으면 완료한다.

## 9단계 — 전체 통합 검증·성능·호환성

### 검사 묶음

1. **콘텐츠 완전성:** 대장 1,305행과 실제 실행 목록을 비교한다. 활성 항목의 참조·효과·드롭·사용처·해금·UI 누락 0건을 목표로 한다. 통합/제외 항목은 대응 ID와 사유를 검수한다.
2. **전투 조합:** 직업 5·전직 10, 스킬·트리·유물·칭호·시설·환생 조합을 계층화해 검사한다. 모든 조합 전수 대신 단일 효과 전수 + 효과 쌍 조합 + 대표 완성 빌드를 사용한다.
3. **진행:** 신규 게임, 기존 저장, 중간층 진입, 보스 재도전, 특수 던전, 도전, 환생을 잇는 시나리오를 수행한다.
4. **저장:** 지원하는 각 스키마에서 최신으로 순차 이전한다. 잘린 JSON, 잘못된 참조, 미래 스키마, 백업 손상, 쓰기 권한 없음, 디스크 부족을 테스트한다.
5. **경제:** 상점↔분해↔제작↔판매, 현상금 생성↔취소, 환생↔초기 보급, 도전↔복원 루프에 대한 자원 복제 검사를 만든다.
6. **중복 입력:** 더블클릭, 키 반복, 결과 확인 재클릭, 저장 재접속으로 보상·포인트·입장비가 중복 처리되지 않아야 한다.
7. **장시간:** 제안 기준으로 100,000개 게임 명령, 별도 8시간 UI 반복 테스트를 수행한다. 무한 루프·로그 무한 증가·메모리 지속 증가·파일 핸들 누수를 검사한다.
8. **성능:** 기준 PC를 명시하고 UI 조회 P95 100ms 이하, 일반 명령 P95 200ms 이하, 첫 화면 5초 이내를 초기 목표로 삼는다. 500턴 자동 전투는 중단/취소가 가능한 작업 단위로 나눠 창 응답을 유지한다.
9. **디스플레이:** 100/125/150/200% 배율, 다중 모니터, 모니터 분리, 최소화·복원, 항상 위, 좁은 화면, 긴 한글·숫자·아이템명을 검사한다.
10. **입력 접근성:** 키보드 초점 순서, Enter 실행, Esc 닫기, 비활성 이유, 툴팁/전체 설명, 검색 결과 없음 처리를 확인한다.
11. **플랫폼:** Windows 10/11 64비트 기준, 한글 사용자명·공백 경로·OneDrive 경로·읽기 전용 설치 위치에서 저장 분리를 검사한다.
12. **보안/실행 안정:** 외부 콘텐츠 경로 탈출, 미지원 연산자, 과도한 값·무한 수치, 잘못된 ZIP/manifest, 동시 실행에 의한 저장 충돌을 검사한다. 콘텐츠는 데이터만 허용한다.

### 결함 등급과 릴리스 기준

- P0: 저장 손실·자원 복제·실행 불가·악성 코드 실행 경로. 0건이어야 한다.
- P1: 진행 불가·핵심 기능 오작동·환생/보상 오류. 0건이어야 한다.

- 장기 밸런스 이슈는 알려진 문제로 남길 수 있지만 모든 직업의 완전한 진행 불가를 단순 밸런스로 분류하지 않는다.
- 원본 보존 해시, 실행 버전, 콘텐츠 버전, 테스트 수, 시드, 환경, 결과 파일 경로를 릴리스 후보마다 고정한다.

## 10단계 — Windows 배포·업데이트·운영 준비

### 패키지

1. 목표는 Python 설치 없이 실행되는 Windows 64비트 패키지다. 패키징 도구는 구현 시 Python 3.15·PySide6 호환성을 공식 문서로 검증하고 버전을 고정한다.
2. 초기 배포는 폴더형 압축 패키지를 기본으로 한다. 실행 파일, Qt 플러그인, 콘텐츠, 문서, 라이선스, 버전 파일을 포함한다. 단일 파일 압축 실행은 초기 기동·백신 오탐 검증 뒤 선택한다.
3. 개발 `.venv`, 캐시, 테스트 결과 전체, 실사용 저장, API 키, 로컬 절대 경로는 포함하지 않는다. 필요한 공개 테스트 요약만 문서로 제공한다.
4. 기본 사용자 데이터 위치는 `%LOCALAPPDATA%/InfiniteDungeon/`로 분리한다. 포터블 모드는 명시적 설정 파일이 있는 경우에만 실행 폴더의 `saves/`를 사용한다.
5. 기존 폴더의 `saves/`를 발견하면 가져오기 미리보기와 백업을 제공한다. 신규 데이터 위치에 저장이 있으면 자동 덮어쓰지 않는다. 슬롯별 가져오기를 지원한다.
6. 동시 실행은 두 번째 인스턴스에서 기존 창을 안내하거나 읽기 전용으로 막는다. 같은 슬롯을 두 프로세스가 쓰지 못하게 한다.

### 업데이트와 복구

- 처음에는 수동 업데이트를 제공한다. 자동 업데이트 서버·계정·온라인 저장은 범위 밖이다.
- 새 프로그램 파일과 사용자 저장을 분리하여 파일 교체 시 저장이 남도록 한다.
- 버전별 변경점, 지원 저장 스키마, 이전 방법, 되돌리기 제한을 안내한다. 최신 저장을 구버전 프로그램이 읽을 수 있다고 보장하지 않는다.
- 릴리스 압축 파일의 SHA-256, 빌드 환경·의존성 고정 파일·생성 명령을 보존한다.
- 로그는 날짜별 크기/개수 제한을 두고 최근 오류를 찾기 쉽게 한다. 개인 경로·진행 데이터가 포함될 수 있으므로 사용자가 선택해 내보내도록 한다.
- 시작 실패는 사용자에게 읽을 수 있는 안내와 로그 위치를 보여 준다. 검은 창만 남는 실패를 재발시키지 않는다.
- 코드 서명 인증서가 없다면 서명됨으로 표시하지 않는다. OS 보안 기능을 끄도록 안내하지 않는다.

### 배포 검수와 완료

- Python이 없는 깨끗한 환경에서 다운로드/압축 해제 → 실행 → 새 게임 → 저장 → 종료 → 재실행을 검증한다.
- 한글/공백 경로, 설치 폴더 쓰기 불가, 오프라인, 이전 버전 저장 가져오기, 프로그램 파일 교체 후 재실행을 확인한다.
- 사용자 안내서는 시작, 학습/재분배, 자동 설정, 제작/수집, 직업, 특수 콘텐츠, 환생, 저장 복구, 알려진 문제를 포함한다.
- 실제 배포 파일을 대상으로 전체 핵심 시나리오를 다시 실행한다. 개발 Python에서의 통과만으로 배포 검수를 대체하지 않는다.
- 산출물: 실행 패키지, 해시, 빌드 명세, 라이선스 목록, 사용자 가이드, 릴리스 노트, 복구 안내.
- 로컬 배포판 검수까지가 구현 완료다. GitHub 업로드·릴리스 공개는 사용자가 요청한 시점에 수행한다.
