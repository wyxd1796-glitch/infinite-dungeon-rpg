# 03-03 — 공통 효과 시점과 저장 재개 계약

2026-10-18 · 계약 버전 1 · 게임 1.2.0 / 저장 스키마 3.

**후속 구현 완료:** 아래는 03-03 당시의 설계/검증 기록이다. 현재 EF016~040은 03-04/05에서 구현했으며 최신 활성 범위·저장 필드·검증 결과는 [PHASE3_EFFECTS.md](PHASE3_EFFECTS.md)를 따른다. 새 전투 규칙 버전은 3, 기존 전투는 기존 버전을 유지한다.

이번 단계는 기존 전투의 공유 처리 지점을 정리하고 EF016~040 구현 계약을 확정한다. **EF016~040은 아직 비활성이고 아래 신규 효과 표는 후속 구현 명세다.** 원본 문자열이나 trigger를 실행 코드로 해석하지 않는다. 원본 1,305개와 활성 260개, 승인된 phase2 스킬·이벤트를 유지한다.

## 1. 실행 경계와 담당 처리기

| 경계 | 담당 | 책임 |
|---|---|---|
| 사용자 명령 | `execute` | 상태·난수 백업 → 실행 → HP/MP 상한 조정 → 난수 상태 저장. 예외 시 상태·난수 모두 복구 |
| 대상 | `actor`, `actor_statuses`, `stats_for` | 플레이어/적 상태 및 능력치를 같은 경로로 조회 |
| 턴 시작/종료 | `actor_phase(side, phase)` | 명시적인 `turn_start`/`turn_end`만 허용, `tick_start`/`tick_end` 연결 |
| 행동불가 | `action_blocked` | 현재 기절·빙결 판정. 플레이어·적·스킬 대기 처리에서 공유 |
| 직접 타격 | `direct_hit` | 명중, 치명, 방어·감소, 실제 피해, 흡혈·반사·반격 순서 |
| HP 피해 확정 | `damage_hp` | 종류별 보호막 처리와 실제 HP 차감. 난수·로그·보상·사망 처리는 호출자가 담당 |
| 사망 판정 | `resolve_deaths` | 플레이어 사망 우선, 이어 적 사망. 승패 처리가 끝나면 후속 행동 중단 |
| 전투 종료 | `victory`, `death`, 도주 경로 및 phase2 정리 | 보상/귀환·진행도·스킬 전투 상태 정리 |

기존 `legacy_pending` 전투는 기존 엔진으로 위임한다. 카탈로그 전투의 상한·신규 처리 규칙을 이전 전투에 강제로 적용하지 않는다. 콘텐츠 버전과 저장 스키마는 별개다.

## 2. 행동 하나의 순서

1. 위치·대상·스킬 학습/해금·침묵·대기시간·MP·소지품을 검사한다. 거절된 명령은 턴·재생·지속시간·난수·자원을 바꾸지 않는다. MP 재생을 먼저 받아 부족한 스킬을 실행할 수 없다.
2. 유효한 행동이면 전역 `turn`과 `combat_turn`을 1 증가시키고 플레이어 턴 시작 재생을 처리한다.
3. 기절·빙결이면 행동만 취소한다. MP/물약은 소비하지 않지만 턴 종료 효과와 기존 스킬 대기시간은 진행된다. 방어 자세도 켜지지 않는다.
4. 실제 행동의 비용을 한 번 지불하고 실행한다. 다단 타격은 타격마다 HP를 확인하며 어느 쪽이든 사망하면 남은 타격을 중단한다.
5. 직접 타격·회복·아이템 효과가 끝나면 승패를 판정한다. 적을 처치했다면 플레이어 턴 종료 지속 피해보다 승리 처리가 먼저다. 마지막 일격 후 남은 독을 그 자리에서 추가로 처리하지 않는다.
6. 전투가 계속되면 플레이어 턴 종료: 상태 목록의 저장 순서로 지속 피해 → 해당 상태의 기간 차감/만료를 처리한다. HP가 0이면 남은 상태 처리를 중단하고 패배를 확정한다.
7. 적 턴 시작 재생 → 이전 방어 해제 → 보스 페이즈 판정 → 행동불가 판정 → 패턴 행동을 처리한다. 행동불가이면 패턴 인덱스는 증가하지 않는다. 침묵이면 특수공격을 일반 공격으로 대체한다.
8. 적의 직접 타격 후 사망을 먼저 판정한다. 살아 있으면 실제 HP 피해가 있을 때 접두어의 명중 후 상태를 부여한다. 보스/원형 효과는 현재 패턴 규칙에 따라 적용한다. 피해가 없어도 자기 강화는 가능하다.
9. 적 턴 종료 효과와 승패 판정을 처리한다. 철벽 방어는 적 행동 기회마다 감소하며 적의 방어·행동불가도 1회로 센다.
10. 전투가 계속되면 기존 대기시간을 1 차감하고 이번에 사용한 스킬의 대기시간을 설정한다. 사용 행동 자체는 새 대기시간을 줄이지 않는다. 전투의 함성은 부여 행동을 제외한 이후 플레이어 행동 3회를 센다. 전투 종료 시 스킬 버프·대기시간·보호막을 초기화한다.

도주 성공은 적 행동 없이 플레이어 턴 종료를 처리한다. 이때 지속 피해로 죽으면 패배로 귀환한다. 탐험에서도 시작 재생→종료 지속 효과를 공유하지만 적 행동은 없다. 이벤트의 비용·환경 피해는 전투 타격이 아니며 별도 이벤트 트랜잭션 계약을 따른다.

## 3. 피해 종류와 순서

| 종류 | 명중/치명/방어 계산 | 보호막 | 흡혈·반사·반격을 새로 발생 |
|---|---|---|---|
| `direct` 일반·강공격·공격 스킬 | 적용 | 적용 | 실제 HP 피해가 있을 때 적용 |
| `counter` 반격 타격 | 적용 | 적용 | 모두 금지 |
| `periodic` 지속 피해 | 미적용 | 우회 | 모두 금지 |
| `reflected` 반사 피해 | 원래 실제 피해의 비율, 별도 명중/방어 없음 | 우회 | 모두 금지 |

직접 피해의 산식/내림 위치는 [BALANCE_SPEC.md](BALANCE_SPEC.md)를 유지한다. 최소 피해 1을 먼저 적용하고 보호막을 차감하므로 실제 HP 피해는 0일 수 있다. 실제 피해는 남은 HP를 넘지 않는다. 피해 통계와 흡혈·반사의 기준은 보호막과 과잉 피해를 제외한 실제 HP 손실이다.

타격 후 순서는 **흡혈 → 반사 → 양쪽 생존 시 반격 추첨 → 승패 판정**이다. 치명타 여부는 피해 계산 중 확정하며 치명 보정은 같은 타격에 한 번만 곱한다. 반사는 피격자가 치명상을 입었더라도 발생할 수 있다. 둘 다 죽으면 플레이어 패배이며 경험치·골드·드롭·처치 회복을 주지 않는다. 반격은 `secondary=True`로 직접 타격 처리기를 재사용하되 재귀 발동을 막는다.

신규 `on_lethal` 처리 위치는 `damage_hp`에서 보호막 차감 후, HP 확정 전이다. 생존 효과가 실제로 막은 양은 실제 피해에 포함하지 않는다. 지속·반사 피해도 이 위치를 통과하므로 별도 생존 우회가 생기지 않도록 한다. **현재는 생존 효과를 실행하지 않는다.**

## 4. 기존 상태·버프의 기간과 중첩

- 기존 상태는 `effect_number`, `effect_id`, `turns`, `stacks`, `applied_at`, `source_atk`를 사용한다. EF001~003은 각각 최대 3/2/3중첩이며 재부여 시 기간은 긴 값을 유지한다. 다른 기존 상태는 1중첩이다.
- 기존 EF002의 공격력 스냅샷은 최초 부여값이다. 재부여는 스택/기간을 갱신해도 `source_atk`를 바꾸지 않는다. 최대 HP 기반 지속 피해는 처리 시 대상 최대 HP를 사용한다.
- `applied_at >= turn`인 상태는 해당 종료 시점에서 피해·기간 차감을 모두 건너뛴다. 새로 받은 재생도 같은 전역 턴에는 발동하지 않는다.
- 기존 호환 예외: 플레이어가 적에게 처음 부여하는 EF001~009는 `applied_at=turn-1`이므로 바로 뒤 적의 종료 시점에 처리된다. 같은 상태를 갱신할 때는 `applied_at=turn`으로 둔다. 이번 단계에서 이 비대칭을 바꾸지 않는다.
- 기절/빙결 자연 만료 시 `cc_until=turn+2`; 이 경계까지 두 효과의 재부여를 막는다. 빙결 자연 만료 후 회피 -5%p 1턴을 추가한다. 소비품으로 제거하는 것은 자연 만료 훅을 실행하지 않는다.
- phase2의 동일 버프는 갱신하며 중첩하지 않는다. 보호막은 기존량과 새 생성량의 최댓값이다. 응급 치료는 기존 중독·화상·출혈 및 legacy poison만 제거한다. 신규 지속 피해를 임의로 제거 대상으로 늘리지 않는다.
- 승리 후 기존 일반 상태는 남아 탐험에서 진행될 수 있다. phase2 전투 버프는 종료 시 제거한다. 새 효과의 전투 종료 제거 여부를 기존 상태 전체에 소급 적용하지 않는다.

## 5. EF016~040의 후속 구현 명세

다음 수치는 원본의 명시적 `magnitude`를 출처로 삼는다. `%`는 100으로 나눈 비율, `%p`는 확률/회피/명중에 더하는 절댓값이다. 피해·회복량은 내림, 양수 지속 피해는 최소 1, 회복은 최소값 보정 없이 0도 허용한다. MP 비용 증가는 최종 올림으로 정한다. 원본 trigger는 아래 실행 시점으로 명시적으로 연결하며, 문자열에서 동작을 추측하지 않는다.

공통 기본값: EF016~028은 상대에게 부여하는 디버프, EF029~040은 자신에게 부여하는 강화다. 부여 확률은 원본 `base_chance_pct`를 사용하고 디버프만 대상 상태 저항을 뺀다. 이미 부여된 효과를 매 타격마다 다시 부여 추첨하지 않는다. 발동 확률(예: 혼란/반격)과 부여 확률은 별개다. 적 원형의 현재 `번호>=10이면 자기 강화` 분기는 이 극성 정의로 교체한 뒤에만 신규 효과를 연결한다.

신규 상태의 기간은 대상의 행동 기회로 센다. 적이 플레이어에게 부여하면 다음 플레이어 행동부터, 플레이어가 적에게 부여하면 바로 뒤 적 행동부터 센다. 자기 행동 중 새로 부여한 강화는 부여 행동을 세지 않는다. 갱신 시 최대 중첩 안에서 증가, 기간은 `max(남은 기간, 새 기간)`이며 갱신 자체로 같은 행동의 차감을 반복 면제하지 않는다. 기존 EF001~015의 호환 예외는 유지한다. 행동불가도 1기회이며 소비·발동 플래그를 갱신으로 초기화하지 않는다.

EF016~028의 제거 태그는 ID별로 선언한다. 신규 `CON016` 만능 치료제는 신규 디버프 전부, 해독제 계열은 EF019, 지정된 후속 아이템은 EF016/017/022/026/028 등 대응 ID만 제거하도록 정의한다. **현재 아이템 동작은 아직 확장하지 않았으며** 03-04/05의 실행 정의와 03-16 소비품 연결에서 함께 검증한다. 존재하지 않는 해제 수단을 UI에 사용 가능한 것으로 표시하지 않는다. 신규 효과는 전투 종료 시 모두 제거하고 기절 면역을 임의로 상속하지 않는다.

## 6. 모호했던 발동·보상·생존 규칙

**EF037:** 상태 한 부여 기간에 처음 맞는 직접 피해에서만 발동한다. `triggered`를 저장하고 같은 상태를 갱신해도 초기화하지 않는다. 기존 상태가 만료/제거된 뒤 새로 부여된 경우에만 다시 대기한다. 생성된 보호막은 현재 공용 보호막 풀의 최댓값을 사용하고 피격마다 재생성하지 않는다. 상태가 만료되어도 이미 생성된 남은 보호막은 소모되거나 전투가 끝날 때까지 유지한다. 이는 원본만으로 확정할 수 없어 정한 실행 보완 규칙이다.

**EF039:** 전투별·대상별 `survive_used`를 상태 인스턴스 밖에 저장한다. 제거·재부여·갱신·저장 복원으로 사용 기회를 되돌리지 않는다. 직접·반격·지속·반사 피해 모두 적용하되 이벤트 HP 비용/환경 피해에는 적용하지 않는다. 양쪽이 생존 효과를 가진 경우 실제 피해 처리 순서대로 각자의 플래그를 소비하고, 최종 사망 판정에서 여전히 양쪽 HP가 0이면 플레이어 패배다. 새 전투에서만 사용 기록을 초기화한다.

**보상:** 적 사망이 확정된 순간 활성 보상 효과를 한 번 스냅샷한다. EF031/040은 `combat_gold` 그룹의 최댓값으로 합치고 기존 장비 골드 보너스에 더한 후 총 +200% 상한을 적용한다. 드롭 추첨·획득 대기 수령·결과 확인에서 다시 곱하지 않는다. 이벤트/판매 골드에는 적용하지 않고, 적 자신의 골드 강화로 플레이어 보상을 올리지 않는다. 기존 처치 회복은 경험치 지급/레벨업 및 드롭 이후 순서를 유지한다. 전투 이벤트 진행도는 승리 처리에서 한 번만 증가한다.

**능력치/MP:** 최대치가 줄면 현재값만 자르고 늘어나거나 효과가 만료돼도 현재값을 채우지 않는다. 레벨업의 기존 전회복은 별도 규칙이다. 새로운 비용 변경은 `skill_reason`, 자동 정책의 예약 MP, UI 비용 표시, 실제 차감을 하나의 함수로 묶어야 하며 사전 검사와 지불 사이에 별도 난수 추첨을 넣지 않는다. 혼란 도입 시 행동의 실제 실행 여부를 공통 결과로 전달해 스킬 대기시간·사용 통계가 잘못 증가하지 않게 한다.

## 7. 저장·재개와 활성화 관문

현재 UI는 `execute`가 동기적으로 반환한 후 저장한다. 타격 사이/보상 지급 중간을 저장하는 API는 지원하지 않는다. 저장에는 상태 기간·스냅샷·보호막·패턴 인덱스·스킬 버프/대기·난수 상태와 확정 이벤트/획득 대기가 포함된다. 복원은 이 값에서 다음 명령을 진행하며 턴 시작 효과나 보상을 미리 재실행하지 않는다. 명령 중 예외가 나면 전체 명령을 취소한다. 자동 전투 명령도 현재 하나의 트랜잭션이며 내부 개별 행동 사이 저장은 하지 않는다.

이번 단계는 새로운 저장 필드를 추가하지 않는다. 후속 EF 구현은 다음 정보를 저장 계약에 추가해야 한다: `battle_rules_version`, 상태의 `source_side`·스냅샷·기간 기준·중복 그룹·발동 여부, 대상별 생존 사용 기록. 실제 필드명/스키마 변경은 03-04/05 구현과 함께 검사하고 03-20에서 통합 이전 검증을 수행한다. **새 필드에 의존하는 효과를 저장 검증보다 먼저 활성화해서는 안 된다.**

기존 진행 중 전투에 규칙 버전이 없으면 현행 계약으로 끝내고 다음 전투에서만 신규 계약을 적용한다. 적·장비·보상 인스턴스는 재생성하지 않는다. 신규 효과 ID만 저장 검증 허용 목록에 추가하는 것으로 구현 완료 처리하지 않는다. 로더·판정·피해/기간 처리·UI 설명·자동 조건·저장 복원까지 연결한 효과만 지원 목록에 넣는다.
