# INFINITE 1.2.0 기준 버전 검수

검수일: 2026-10-17 · 게임 1.2.0 · 저장 스키마 3

## 현재 판정

로드맵 1단계의 자동 검증과 복구 가능한 소스 기준점 준비를 마쳤다. 실제 Windows 배율·다중 모니터와 수동 플레이 승인은 남아 있다. 따라서 1단계 전체 완료나 배포 승인을 의미하지 않는다. GitHub 업로드는 수행하지 않는다.

원본 카탈로그는 변경하지 않는다. `.venv/`, `saves/`, 시작 로그, `desktop.ini`, 임시 검수 저장은 버전 관리에서 제외한다.

## 이번 실행 결과

| 검사 | 결과 | 범위 및 제한 |
|---|---|---|
| 변경 전 회귀 | 100개 통과, 14.305초 | 현재 작업 폴더의 기존 테스트 |
| 최종 회귀 | 101개 통과, 14.871초 | 추가 테스트 1개 안에서 저장 14종 검사 |
| 저장 이전 | 14종 통과 | v1 거점/전투/선택/초과, v2·v3에 결과 대기 추가 |
| 보존 | 통과 | 원본 바이트, 백업, 장비 참조, 재화, 스킬 투자, 적, 이벤트, 상점 재고, 재저장 후 상태 |
| 획득 초과 | 통과 | 99개 초과 4개 보존, 다시 불러와도 증가 없음 |
| 실행·종료·재실행 | 4회 통과 | main.py·start.bat 각각 2회, 종료 코드 0, 정상 창 생성 및 종료 저장 |
| 시작 실패 로그 | 통과 | 임시 복사본에 예외를 주입하여 startup 로그에 예외가 남는지 확인 |

실행 검수는 Qt offscreen에서 실제 진입점을 호출하되 테스트 전용 `sitecustomize.py`로 저장·설정 위치를 임시 폴더로 바꾸고 자동 종료한다. 실제 바탕 화면에서의 창 표시·포커스 검사는 아니다. BAT 정상 검수는 현재 설치된 가상환경 경로를 사용한다. 실패 로그 검수는 가상환경 없는 복사본에서 PATH의 Python 경로를 사용한다. 깨끗한 PC의 설치 검증은 후속 배포 단계다.

저장 fixture는 각 엔진으로 만든 **합성 데이터**이며 과거 실사용 파일을 수집한 것이 아니다. 고정 시드로 같은 상황을 생성하지만 장비 UUID와 생성 시각까지 바이트 단위로 동일하게 만들지는 않는다. v1에는 당시 없던 결과 확인 화면을 억지로 추가하지 않는다.

## 재현 명령

프로젝트 폴더에서 PowerShell로 실행한다.

```powershell
$env:QT_QPA_PLATFORM='offscreen'
.\.venv\Scripts\python.exe -m unittest discover -s tests -q
.\.venv\Scripts\python.exe -m tests.release_fixtures
.\.venv\Scripts\python.exe -m tests.verify_release_launch
```

생성한 저장은 `artifacts/release_1_2/fixtures/`, 실행 결과는 `artifacts/release_1_2/launch.json`에 둔다. 생성 도구는 실사용 `saves/`를 읽거나 덮어쓰지 않는다. 수동 검수에서 fixture를 열 때에도 별도 복사본과 별도 저장 경로를 사용한다.

## 남은 수동 검수표

각 항목은 실제 확인 후 날짜·환경·관찰 결과를 기록한다. 기존 자동 테스트 통과를 수동 확인으로 대체하지 않는다.

- [ ] Windows 탐색기에서 BAT와 main.py 실행 → 화면 표시 → 종료 → 재실행. 검은 창만 남지 않는지 확인.
- [ ] 신규 게임에서 보급 구매 → 입장 → 전투 → 회복 → 저장/불러오기 흐름 확인.
- [ ] 스킬 잠금/미학습, 학습·최대 레벨, MP 부족·침묵·행동불가·쿨다운 사유, 자동 켜기/끄기와 동순위 ID 정렬 확인.
- [ ] 거점에서 재분배를 두 번 시행하고 포인트·현재 HP/MP가 증가하지 않는지 확인.
- [ ] 이벤트의 골드/아이템/HP 부족 표시, 성공·실패 문구, 전투 연결, 결과 확인 후 계속하기, 가방 초과 획득 대기 확인.
- [ ] 268×861 및 250×400 창에서 설명/잠금 사유를 스크롤로 모두 읽을 수 있는지 확인.
- [ ] Windows 디스플레이 배율 100%, 125%, 150%에서 위 두 크기를 확인. Qt의 offscreen 결과와 구분.
- [ ] 최소화 → 복원, 항상 위 핀 설정 → 재실행, 다른 모니터로 이동 → 종료/재실행, 모니터 분리 후 화면 안 복원 확인.
- [ ] 관찰된 결함은 재현 조건과 수정 테스트를 기록하고 전체 회귀 검사를 다시 수행.

## 기준점과 복구

이 문서를 포함하는 로컬 커밋 제목은 `Finalize 1.2.0 baseline and release verification`으로 한다. 생성 여부와 해시는 실제 Git 기록으로 확인한다. 이전 소스 기준은 `555e172`이다. 기존 실행 문제가 있었으므로 이전 커밋만으로 현재 PC의 실행이 보장되는 것은 아니다.

복구 시 현재 폴더를 강제로 되돌리기보다 `git archive <기준커밋> -o <새 ZIP 경로>`로 소스를 별도 위치에 내보낸다. 가상환경·실사용 저장은 Git에 없으므로 별도로 보존해야 한다. 이전 저장 백업은 `.pre-v2.bak`, `.pre-v3.bak`으로 보존하며, 검증은 그 복사본으로 한다. 현재 저장을 과거 코드에 직접 덮어쓰지 않는다.
